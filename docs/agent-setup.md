# 把下载、安装和打开交给 Agent

把 [README 中的安装 prompt](../README.md#开始使用)发给能操作本机的 Codex、Claude Code、Gemini CLI 等编码 Agent 即可。你不用先下载源码、准备 Python 或手动敲安装命令。Key 在本机页面填写，QQ 平台授权由你本人完成。

下面是给执行安装的 Agent 的流程。请直接完成下载、环境准备、安装和启动；普通安装错误自行定位、修复并继续。需要账号登录、系统许可或管理员操作时，再交给用户完成。

## 1. 取得可用的正式版源码

项目地址：<https://github.com/dubianche123/the-regular-qq-bot>。

查询 [最新正式 Release](https://github.com/dubianche123/the-regular-qq-bot/releases/latest)，取得其实际标签，下载对应的 **Source code (zip)** 并完整解压；有 Git 时也可以克隆后使用同一标签。使用独立源码目录，不把程序放进私有数据目录。不要把仓库 `main` 的未发布内容当成正式版，也不要只下载缺少启动文件的 wheel。

阅读下载版本的 `AGENTS.md`、`docs/getting-started.md` 和 `docs/companion.md`。具体命令与可用功能以该版本为准；本页的新版本说明不代表旧安装已具备同样功能。

如果已经安装，先确认原源码位置、实例路径和运行状态，沿用原来的私有配置与数据。不覆盖 `.env`，不新建一个空实例来代替已有实例，也不重启其他机器人。

## 2. 准备环境并使用现成启动器

检查本机系统、Python 3.10+、图形桌面和依赖下载条件。已有合适的 Python 就复用；缺失时通过官方发行渠道或本机可信包管理器安装。系统要求人工确认时请用户完成，不关闭安全保护。

源码目录应包含 `start.bat`、`start.command`、`start.sh`、`tools/start_regular.py` 和 `pyproject.toml`。默认实例路径为 `~/.the-regular`；已有实例使用原路径。以下命令中的路径由你填好，不交给用户猜：

| 系统 | 从源码目录启动 |
| --- | --- |
| Windows | `start.bat --directory "<实例目录>"` |
| macOS / 有桌面的 Linux | `bash start.sh --directory "<实例目录>"` |

启动器会创建源码目录里的 `.venv`、安装项目依赖，并在 macOS 构建名为「老群友」的应用。保持启动进程运行，等到人物实际出现；安装错误要读报错后修复，不要只回报“命令执行了”。Linux 缺少 `venv` 或图形运行库时，使用发行版的对应包补齐。

全新无图形桌面的 Linux，在源码目录创建环境并安装基础依赖，再启动本机工作台：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python -m regular --directory "<实例目录>" panel
```

已有合适环境时直接复用。说明该环境无法显示透明桌宠；原生组件不可用时先排查依赖，确需网页替代时可用 `pet --browser`。面板保持本机绑定，不把带 token 的地址公开转发。

## 3. 打开人物旁的工作台，配置留给用户的部分

靠近人物，确认五个按钮围成圆环，点 **「更多 → 打开工作台」**。你负责打开页面、补齐公开参数；用户只需在本机页面输入自己的 Key 和 QQ 凭据。

- **官方 OpenAI**：在「模型与能力」顶部独立连接 Key，使用项目的聊天主备、判断和其他能力预设。不让用户查模型 ID；保留已有模型选择、单独配置的服务和已关闭的能力。
- **其他服务或兼容地址**：按该服务实际支持的接口和模型配置。不同服务使用各自凭据，不把官方 OpenAI Key 发往其他地址。
- **QQ**：带用户打开「QQ 连接与身份」填写 AppID、AppSecret 和名字。QQ 平台登录、事件订阅、测试成员与使用范围由用户本人完成；你不代发第一条私聊认主。

密钥只在本机填写和保存，不要求用户贴到 Agent 聊天里，也不在日志或最终报告打印。保存配置不调用模型。核对读图、画图、听语音、发语音和桌宠语音各自的开关、参数与本地依赖；参数齐全不等于账号已有接口权限，不为安装验收自动画图、发语音或试调付费模型。

### 安装版本还没有自动预设时

例如已发布的 `v0.5.0` 源码包仍会留下空模型字段、要求首次保存判断连接。这些步骤由 Agent 补齐，不再推回给用户：官方地址使用 `https://api.openai.com/v1`，聊天主备使用 `gpt-6-luna` / `gpt-6.1-terra`，判断和视觉使用 `gpt-6-luna`；其余能力保留该版本已提供的模型与有界额度。用户填好 Key 后，由你在本机保存同源的共享判断连接，无需第二把 Key。

上面是旧版的公开配置补齐方式，不覆盖用户明确保存的值；新版已有默认值时直接沿用，不重复生成配置文件。配置位置、能力开关和生效方式见[模型与能力](capabilities.md)与[模型服务](providers.md)。

## 4. 验收实际结果，再交给用户

使用这个安装环境的 Python 运行 `-m regular --directory "<实例目录>" doctor --json` 做只读检查。缺少尚未由用户填写的 QQ 凭据是待接入事项，不等于桌宠安装失败。

逐项确认：

1. 有桌面时人物确实可见，悬停圆环可打开；网页替代时说明实际打开的是网页。
2. 本机工作台能打开，保存后仍沿用同一实例；已有配置保留。
3. 用户在本机填好配置并确认 QQ 授权完成后，按这次委托继续启动机器人，用 `status --json` 确认实际 QQ 网关已连接，无须再问一遍是否启动。尚未完成配置时，先交付可见桌宠和工作台。由用户发第一条非空私聊完成认主；不自动发群测试消息。

最后用几句话交付：安装的实际版本、源码与实例位置、当前已就绪和待用户完成的事项，以及再次打开与退出的方法。关闭人物或网页不会停止机器人；退出本次面板服务会停止它自己启动的机器人，已有外部服务仍由原入口管理。

安装后需要调整群聊表现，去工作台「让她更好」复制交接说明，再附上反馈。真实群聊回放和自迭代另走仓库的 [regular-iterate skill](../.agents/skills/regular-iterate/SKILL.md)。
