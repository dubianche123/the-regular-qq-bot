# 从真实群聊判断何时值得个性化

2026-10-30。本文保留双向记录的设计与可选研究备忘，不是产品迭代的前置流程。
The Regular 首先是好玩的群友：自然反应可以直接指导暂时退让、修正和接话，
不必等显式评分。判断 API 的产品接入见 [判断帮手](providers.md#原生判断帮手)；
下面的概率、对照和反馈标签讨论不构成正常聊天或使用记忆的门槛，也没有开启随机实验。

## 历史数据决定了先补什么

本地 2026-10-23 迁移快照的检查结果已经单独保存，不在本项目发布原始数据：

- 1,782 条收到的群消息，覆盖 26 个有记录的日期，时间为 09-16 至 10-23。
- 一个群、九个发言者标识；主要互动集中在六人，每人 120–559 条。
- 只有 182 条带消息标识；状态快照仅保留三段会话里的九对问答。
- 包中没有完整运行日志，22 份每日摘要也不能替代缺失的机器人原话。

这些数字描述这份备份，不代表家里机器的全部历史。发言标识也不等于经核实的
独立实验参与者。检查没有把辱骂、示好、继续聊天或模型摘要转成偏好标签。

实际片段同时出现喊停、催机器人回答、起哄和钓鱼。可见需要区分至少四件事：
是否该插话、是否接对当前话题、是否具备所需能力、语气是否合适。
先修正大家都会遇到的问题，再问个人信息是否带来额外帮助。

## 两份记录各司其职

`archive/` 继续保存收到的群友消息，供来源核对、摘要和显式旧账查询使用。
`interactions/` 独立保存互动事件，既不进入模型上下文，也不参与人物摘要。
不能把机器人说过的话再当成群友的原话，或把反馈指令变成人格描述。

互动事件按本机日期写入 JSONL，基础字段为：

| 字段 | 含义 |
| --- | --- |
| `schema` | `regular.interaction.v1` |
| `event_id` | 本地事件标识，不发到群里 |
| `ts` | 事件记录时间，Unix 秒 |
| `kind` | `incoming`、`decision`、`delivery`、`feedback`、`natural_feedback` 或 `decision_scores` |
| `group` | 本地关联用的群标识 |
| `user` | 本次互动关联的群友；不是统一的“输出作者”字段 |
| `actor` | `user`、`system` 或 `assistant`，明确谁在行动 |

不同事件记录不同事实：

- `incoming`：规范化后的收到全文、消息标识、直接唤起和本地指令标记。
- `decision`：直接接话或插话闸门的结果；有抽样时保存实际概率和那一次抽样值。
  搜索覆盖、模型选择沉默、预算阻断分别留痕，不能合并成用户不喜欢。
- `delivery`：一次逻辑发送的 `outgoing_id`、来源消息、参与方式和送达状态。
  **只有确认送达的事件包含作为群内发言的实际全文**，包括发送前追加的提示和平台兜底。
- `feedback`：用户主动给出的评价、对应的已送达事件，以及对旧评价的修订关系。
- `natural_feedback`：有效的自然反馈解释，记录目标、建议与实际采用的动作、对应的已送达 bot 发言；这是产品判断，不冒充用户明确打分。
- `decision_scores`：一次原生判断的**数值**留档。`site` 区分四个产品位置
  （`feedback` / `banter` / `callback` / `memory`），逐题记下选中的选项、
  自己算的边际（被选中项比第二名高多少）、原生返回的 `confidence`，
  以及这一题有没有被弃答闸丢掉（`dropped`）；`min_margin` 记下当时的地板。
  2026-10-31 之前这些数值在解析完就被丢掉，于是「以后拿真实结果去校准产品判断」
  永远缺原料。**它只记数，不记原话、不记身份** —— 那两样归 `archive/` 管，
  有测试盯着。题数超过 40（原话裁决一次能问几十题）时只记条数不记明细。
  行里还带 `source_message_id`（哪条群消息触发了这次判断）和每题被选中项的
  概率 `p` —— 这两样是为了让离线拼标签走**显式标识**而不是时间对齐。
  这些数值的刻度**不能**当概率用，原因与测量见
  [判断概率值得信到什么程度](decision-calibration.md)。

`queued` 不是已经说过，`expired` 不是主动沉默，生成成功也不是送达成功。
后续补投继续关联同一个逻辑发送；主动群发没有虚构的触发消息或个人评价对象。
平台回执只取可用的消息标识，不落盘整个 SDK 对象。

插话闸门概率只描述这道闸门，后面还有预算、模型沉默与发送失败。
它不是最终送达的倾向概率，更不是随机实验的分组概率。

模型归属来自实际成功的候选调用；未知时保留未知，不拿配置列表第一项代替。
个人原话是否注入来自实际组装路径，不根据好感档位或仅仅打开开关推断。
知识库、旧账和搜索的 `*_supplied` 标记只表示调用方提供过这些材料，
不冒充它们一定通过了当轮注入条件。
`policy_id` 是操作性版本标签；它不等于已经冻结了实验中的代码、提示词和配置。

## 明确但不打扰的反馈

这是可选的本地排障入口，不是机器人接受反馈的唯一渠道。正常的喊停、纠正、继续接梗和
后续提问也能进入判断帮手，群友不需要改写成下面的语法，机器人才肯调整。

群友可以直接发送以下本地指令：

```text
反馈 合适
反馈 不合适 时机
反馈 不合适 内容
反馈 不合适 语气
反馈 不确定
```

语法为 `反馈 <合适|不合适|不确定> [整体|时机|内容|语气]`，默认维度为整体。
单独发送 `反馈` 查看用法。它不经过模型，不消耗模型预算，也不改变交情或心情。
机器人不会自动追问，更不会因为有人未评价就把他记成不满意。

默认只关联最近 30 分钟内，机器人在**同一群里对本人**实际送达的最近一次
AI 会话接话；直接回应和随机插话均可。本地指令回复、反馈确认、主动群发、
其他人的回复和未送达内容不作目标。超出窗口或无法保存时会明确说明，没有评价成功的假回执。
这 30 分钟是关联窗口，不是个人偏好的有效期或统计上的启用门槛。

再次评价同一条回复的**同一维度**会追加修订事件，用 `supersedes` 指向旧评价，
不覆盖原记录。“内容合适”和“时机不合适”可以并存，不会互相覆盖。
这些维度仍属于同一次互动，不能当作多个独立互动。分析某时刻的可用信息时，
只能采用当时已经到达的修订，不能借用后来改过的答案。

“不确定”表示没有得到明确的好坏标签，但仍然是一笔真实的反馈付出。
反馈维度是用户明确选择的维度，不是模型诊断出的原因。
这套关联仅覆盖本人最近一次接话，不冒充支持评价任意群消息或旁观者投票。

## 配置与本地保管

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `INTERACTION_LOG_ENABLED` | `true` | 开启本地互动记录；关闭后反馈不会声称已保存 |
| `INTERACTION_LOG_DIR` | `DATA_DIR/interactions` | 独立事件目录；旧布局可能位于实例根目录 |
| `INTERACTION_FEEDBACK_MAX_AGE_SECONDS` | `1800` | 最近一次本人回复的反馈关联窗口 |
| `INTERACTION_POLICY_ID` | `regular-observe-v1` | 操作性版本标签 |
| `DECISION_MIN_MARGIN` | `0.25` | 弃答地板：边际低于此值的那一题当作不可用，退回基线；`0` 关闭 |
| `ARCHIVE_KEEP_DAYS` | `90` | 原归档和互动记录的保留天数；`0` 表示不自动清理 |

新记录沿用本机运行数据的保管边界：不上传外部服务，不写进 Git，不送入模型。
迁机和备份时把 `interactions/` 与原有 `archive/`、`state.json` 一起带走；
迁移文件不应公开发布。关闭当前记录不会删除已存在的历史文件。

写入失败不会阻断正常聊天，但意味着记录可能有缺口，不能补造事件。
每行追加并刷新不等于崩溃后绝不丢失，回执确认也不代表已经获得用户评价。
C2C 私聊不在这条群聊记录管线里。

这是本地运行记录和可选的产品反馈功能，不自动构成论文研究招募。
将来要把群友的新互动用于研究，应讲清用途、可见范围与自愿参与方式；
原始聊天、身份映射和可分享的匿名分析分开保管。

## 下一步研究什么

下面是研究路线草案，不是已经冻结或执行的实验协议。
新日志不代表已经有足够评价，更不代表已经发现了个人模型的收益。

### 第零步：先量个人原话的实际覆盖率

```bash
regular --directory . coverage --json
```

这是本机只读统计，不连接 QQ、不调用模型、不启动运行时，也不修改日志。
它读取当前保留下来的互动 JSONL，不用今天的摘要或档案重演过去的准入判定。
两天指原话在生成当时的有效期，不是本命令的统计时间窗。

主分母是可明确识别的、实际送达的会话模型回复：`route=reply/banter`、
`generation=model` 且不是平台兜底。同一群的同一个 `outgoing_id` 只计一次，
排队与补投不重复计数。本地指令、主动广播、本地兜底、平台兜底、未确认送达、
模型沉默和预算阻断均不属于这项已送达模型回复的分母。
缺少生成来源或兜底标记的旧记录另列为无法分类，不擅自认作普通模型回复。

- `injected`：`personal_memory_used` 明确为 `true`。
- `not_injected`：该字段明确为 `false`。
- `unknown`：该字段缺失或不是布尔值，不能按未注入处理。
- `injection_rate = injected / (injected + not_injected)`，只在有可测记录时给数值。
- `trace_fraction` 报告主分母中有明确注入记录的比例；同时报告未知数。
- `injection_rate_bounds` 将未知记录分别全当未注入/已注入，只是缺失信息上下界，
  不是统计置信区间，也不涵盖已排除的无法分类记录。

按直接接话/随机插话、特性开关状态和群内账号分层。当前随机插话刻意不注入；
关闭特性也不是话题匹配失败，不能只看整体比例就下结论。总比例会受活跃账号支配，
要同时看每个账号的机会数，不能把消息多当独立用户多。
`by_user` 实际按群和账号组合分层，不把跨群标识或不同日期当独立真人；
显示别名仅在这份报告内有效，不输出身份映射、原话或回复全文，
但小群里的计数本身仍可能被熟人认出，不承诺匿名化或直接公开。

没有日志或没有可判定是否注入的记录时，比例为 `null`，不是 `0%`。
至少观察到一次明确未注入且没有已注入，才可能得到真实的观测零值。
坏行、读取错误、重复送达和无法分类记录都单独计数；日志缺口不能补造，
统计结果只覆盖可读取记录。命令在没有可测记录或发生读取错误时退出码为 1，
仍可从标准输出取得 JSON。

这测的是**当前可观察的实际使用频率**，不是关闭特性时潜在的可用机会、
所有生成尝试的覆盖率，也不是因果收益。低覆盖说明当前功能日常触达有限，
不等于“普通回答足够”已经被验证；少见情境也可能有价值。
是否值得继续试验还取决于每人的机会数和愿意给出的明确反馈，
这里不设一个自动进入试验的覆盖率阈值，也不为刷覆盖率放宽来源要求。

### 原话注入的后续对照：只在合格机会中随机

这是与下文插话时机研究不同的任务。若未来数据与自愿参与条件允许，
先冻结协议，再在同一人原本符合来源、话题、时效与产品闸门的接话中，
随机分配“本人相关原话”和“不追加原话”。不是随机换一个人的背景，
不改变称呼、游戏关系和其他资源预算来制造差异。

记录合格条件、实验分组、实际分配概率、实际注入、生成与送达结果，
以及本人明确给出的评价；分配不保证最终生成或送达，要保留偏离分配的情况，
不能只挑成功注入且愿意给好评的回合比较。
资格判断发生在分配之前，不能用 `personal_memory_used` 事后圈选合格样本。
当前的注入标记只是观察记录，不能事后冒充随机分组或推算分配概率。
会话历史中的先前回复可能留下跨轮影响，连续回合也不是独立样本，
这些条件需在正式协议里处理。

真群只用本人材料或不追加材料，**不运行错配对照**。错配只能用于隔离离线诊断，
不向群友发送，不把别人的原话冒认到当前人头上。接话是否合适以本人评价为准；
LLM 可以被研究为预测器，但不能兼任标签真值或效果裁判。
缺失和“不确定”不补成好坏，模型自评、好感、辱骂或沉默均不替代本人评分。
本轮没有启用这个随机试验，也没有设置分配概率或自动提问。

### 第零步之二：核对判断说的概率对不对得上现实

```bash
regular --directory . calibration --json
```

同样是本机只读统计，不连 QQ、不调模型、不改日志。它把
`decision_scores` → `delivery` → `natural_feedback` 三跳按显式标识拼成
(预测概率, 真实结果) 对，回答一个问题：**决定插话时，它说的那个概率准不准。**

能回答的和不能回答的分得很清：

- 只覆盖**决定开口**的那些判断。`stay_quiet` 之后机器人不说话，
  所以那些时刻的结果是**审查**，不是负例，也不在这份报告的射程内。
- **没人反应是缺失标签**，单独计数，绝不补成负例。
- `repair_briefly` 这类谈内容的结论不算「打扰该不该」的标签。
- ECE 带 Bernoulli 零假设，Platt 斜率带自助区间；样本不足时报条数而不是比例。
- 这是观察记录，不是随机实验：插话由产品闸门决定，标签里混着选择效应。
  **用它学一个阈值正当，用它声称因果收益不正当。**

为什么要有它：判断返回的概率**刻度不可用**（实测 ECE 0.22、Platt 斜率 0.21），
而文献里有效的修法是拿十到二十条带标签样本学一个阈值
（[判断概率值得信到什么程度](decision-calibration.md)）。
那十到二十条就该从这条回路里长出来，而不是另造一个标注流程 ——
这也是「下一句骂你就是反馈」在研究侧的兑现方式。

### 第一步：判断一次接话是否合适

插话时机方向另固定一个小任务：对实际送达的一次回复，预测本人会不会认为这次接话的
**时机**合适。只使用明确选择“时机”维度的二元评价；整体、内容和语气另行描述，
不擅自把它们合并成同一标签。“不确定”不补成二元答案，并单独报告。

这是对已发生回复的评价预测，不是直接证明换一种回复或保持沉默会更好。
没有回应的群友、没被评价的回复仍然是缺失反馈，不能补成负例。
主动使用反馈指令的人可能与不反馈的人不同，观测结果先限定在可评价的互动上。

在相同当前群聊情境、同一条实际回复和同样反馈预算下，比较三层预测：

| 比较对象 | 它能够学什么 |
| --- | --- |
| 群体情境模型 | 其他用户共同的接话规律，不使用目标用户的历史评价 |
| 简单个人校准 | 在群体模型上，修正此人总体更欢迎或更不欢迎接话的倾向 |
| 个人情境模型 | 在前两者之外，学习这个人在不同情境下的额外偏离 |

简单个人校准已经是个性化，不能再叫纯群体基线。
“普通友善回复”则是产品行为基线，不是凭名称就成为了群体偏好预测器。
对每个人重新训练一个很大的模型，也不是此处的研究目标。

先用较长记录检查个人情境收益是否存在，再判断少量反馈能不能识别
**当前预算下**的收益。不能拿“以后记录很多时能学好”当成“现在就该启用”的标签。
这对应 Norn 的核心区分：个人差异、模型信心和个人模型的额外收益是三件事。

### 第二步：判断什么时候启用

草案按前 2、4、8 次实际反馈动作检查启用判断；最终预算和可用样本条件在
未来协议中另行冻结。修订和“不确定”也消耗反馈动作，不能只计算成功取得的标签。
训练时每条回复的每个维度至多使用截至当时可见的最新明确评价，
不把不同维度合并，也不用未来修订倒改历史。

严格区分两个设定：

- 冷启动回放：模型只见当前情境与预算内反馈，不从后来的摘要、关系档案或完整历史偷看。
- 多聊天、少评价：额外允许已经听到的聊天历史；单独报告这些历史的信息量。

旧群友的早期回放不称新真人验证。不同日期的同一人也不是新的独立用户。
训练、收益判断校准和最终评价按用户及时间分开，连续话题不能跨切分泄漏。
现有小群适合开发和纵向案例；跨用户、跨群的结论需要相应的新数据。

启用策略与始终群体、始终个人、简单固定反馈预算策略比较。
草案以之后明确二元评价的 Brier 损失为预测指标，按人汇总；同时报告启用覆盖、
被启用者的后续损失差、观测到的变差、未判比例及真实反馈付出。
少量留出评价上的变差不是已经确定的个人期望风险，不能包装成人身安全保证。

若只是“所有人都少打断一点”就改善，应归给共享策略；若只需一个人的总体参与倾向，
也应先承认简单个人校准已经足够。个人情境模型需要在这些基线之上再取得收益。

### 第三步：让提问服务于启用决定

在前两步已有可用基线之后，再设计自愿的低频确认。
选择的问题应帮助减少“个人模型是否值得启用”的不确定性，
不只是让偏好参数更精确，也不只追求模型分歧最大或聊天更多。

后续比较随机提问、一般不确定性提问和决策导向提问，使用相同可见信息、
反馈预算、候选情境和模型资源；未回答的提问曝光也计入打扰成本。
选择问题之前不能读取尚未得到的用户答案。
提问可能改变实际互动，因此历史回放不能替代前瞻比较。

当前版本没有这个主动提问策略。插话骰子是产品机制，不是论文的随机实验。
想证明“启用之后聊天更合适”，还需要对实际行动的前瞻对照；
评价预测改善不自动等于接话质量、信任或参与感改善。

## 本轮交付边界

本轮补全可关联的双向事件、实际送达、参与决策和明确评价入口。
不从旧档案造反馈，不因好感高就启用个人模型，不把模型自己的情感分值当真人评分。
既有 Norn 实验、冻结文件与结果不变；没有额外付费回放、模型训练或线上重启。
来源准入和个人原话注入的已有边界见 [交情与个人证据](personal-memory.md)。
