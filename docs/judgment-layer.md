# 判断层：什么交给 Decisions，什么留在代码里

2026-10-31。群主的要求是「想清楚这玩意怎么用」，并且可以大刀阔斧。
这篇回答三件事：它到底是什么、哪些活该交给它、交过去之后失败了往哪边退。
所有数字都来自 U 盘归档的真实群聊；合成样例会单独标出来。

配套阅读：[判断概率值得信到什么程度](decision-calibration.md)（为什么只信排序、不信概率）、
[何时介入](when-to-intervene.md)（节奏与接纳度）、[叫到我不等于要我答](addressing.md)（这次改动的地基）。

---

## 一句话

Decisions 介于正则和大模型之间：**它只做「把一句人话归进一个封闭的选项集」**。
按输入计费、输出不要钱、逐位确定、亚秒级。所以用法是：

> 每条跟机器人有关的消息只建**一份** payload、发**一次**调用、挂上所有用得着的题；
> 每个选项都是代码会采取的**一个动作**；判断不可用时往哪边退，按这个动作的代价定。

## 一、这个接口实际是什么（测出来的）

| | 实测 |
| --- | --- |
| 价钱 | 群主给的价：输入约 0.1 美元 / 百万 token，输出不要钱。题目本身也是输入，但远比把对话送过去便宜。本群 917 条点名消息全部分诊一遍约百万 token 量级 ≈ 0.1 美元（估算，没有逐条计 token） |
| 延迟 | 908 次分诊：中位 **0.71 s**，p90 1.20 s，最慢 3.8 s |
| 确定性 | OpenAI 同一 payload 逐位相同；Jev 会抖 ±0.01–0.03（见 decision-calibration.md 第八节） |
| 擅长 | **意图 / 路由**：分得清「在问它」「在逗它」「在说别人」 |
| 不擅长 | **绝对概率**：刻度跟着基础率漂（同一任务两个时段，基础率涨 0.17，它的平均输出只跟了 0.07） |
| 时好时坏 | **靠知识的识别**：谐音政治人名有把握拦下一半，也有把握放行过一个 |
| 拿不准 | **短、缺语境的条目**：单独一个「老王」要不要当称呼，五次里四次边际不到 0.25 |
| 做不到 | **写**：只能选，不能抽取。「叫我 X」里的 X 还得本地取出来 |

所以：选项就是路由，**只信排序和有把握的结论**，不拿它的概率当概率。

## 二、四类活，四个归宿

| 活 | 例子 | 谁做 | 为什么 |
| --- | --- | --- | --- |
| **解析** | QQ 标签、@、机器 ID 脱敏、输出里的 `<CMD>` | 代码 | 格式是确定的，错一个字符就是 bug |
| **规则** | 群主身份、认领、敏感词表、预算、改名节流 | 代码 | 不能依赖远端可用，也不能被话术绕开 |
| **判断** | 是不是在叫它、该不该答、要不要翻旧账、是不是嫌烦、这是不是起名 | **Decisions** | 人话是开放的，枚举永远补不完 |
| **抽取** | 昵称是哪几个字、旧账里搜什么词 | 代码提议，Decisions 裁决 | 它只能选，不能写 |
| **生成** | 回复正文、摘要 | 大模型 | 开放文本 |

**判断不再让生成顺手做。** 以前「说不说」是写回复那一步用 `SKIP` 顺手决定的 ——
花一整次生成去决定不生成，而且人设里还得写一段「被点名时尽量别用」。现在「说不说」
在生成之前由判断决定，生成被叫到就一定写。

**指令触发词不是判断，是界面。** 「摇骰子」「关系榜」是按钮上的字，用户靠它们的精确性；
真实归档里它们几乎没被用过（多数 0 次）。不迁。

## 三、判断不可用时往哪边退

| 这道判断守的是…… | 不可用 / 拿不准时 | 为什么 |
| --- | --- | --- |
| **欠人家的一句回答**（被点名） | **答**（= 今天的行为） | 被叫到却被无视，比多答一句难受 |
| **多出来的东西**（翻旧账、主动开口、端旧话、短接一句） | **不加** | 新增的东西不许靠失败兜底 |
| **会留下来的写入**（称呼） | **照旧走底线**，判断只能否决 | 见第五节：它批准不了一个普通名字 |

「拿不准」= 边际（选中项比第二名高多少）低于 `DECISION_MIN_MARGIN`（0.25）。
一份返回里某一题坏了（比如起名那题碰上政治人名被拒答），**只作废那一题** ——
`parse_each` 逐题校验，`parse_answers` 保留全有或全无给需要它的地方。

## 四、分诊：一条消息一次调用

`regular/decisions.py` 的 `FeedbackTracker.assess`。本机先看已知事实，再决定挂哪几题：

| 本机已知 | 挂上的题 |
| --- | --- |
| 机器人 2 分钟内说过话 | 反馈四题：冲谁说的 / 下一步 / 要不要接 / 插不插 |
| 正文里有名字（不是平台 @） | `addressed`：answer / quip / let_it_pass |
| 被 @ 或被点名，窗口内没回复 | `next_move`：只用来判断语气要不要收敛 |
| 会正经回复，且开了召回 | `recall`：look_up / no_need |
| 本地起名模式提出了候选 | `nickname`：adopt / refuse / not_a_request |
| 只要问了任何一题 | `intervention` 永远带上 —— 骰子掷中时直接复用，不发第二次 |
| 跟机器人无关的普通消息（`DECISION_TRIAGE_ALL=true`，默认） | 只问 `intervention` |

开关关掉时，一题都用不上就 0 调用。`bot.py` 里第一次需要时才问（起名在 5.5，其余在 9），之后复用。

**边界（刻意的）：**

- **每条群消息都问一次**（群主 2026-10-31 的决定：「大不了之后收集够数据再调整减少」）。
  这意味着每条群消息都以脱敏形式发给 OpenAI。好处是「何时介入」那一题从此每条消息都有数，
  而不只是骰子掷中的那一成多 —— 以后换掉骰子、按排序决定插不插，靠的就是这批数据。
  `DECISION_TRIAGE_ALL=false` 退回「只问跟机器人有关的」。
- **判断有自己的日额度**（`DECISION_DAILY_BUDGET`，默认 5000），和聊天的 `DAILY_BUDGET`
  分开记：每条消息都问之后，刷屏不能把当天的回复额度烧光，回复也挤不掉分诊。
  额度用完就当判断不可用，按第三节的表退。
- **私聊不分诊。** 私聊是最私密的那一路，同理不新开数据流；喊停照旧靠本地词表。
- 群号、openid、消息 ID 照旧在本机抹掉；命中敏感词表的材料整条不出本机
  （起名候选命中词表时，那题干脆不问）。

## 五、迁了什么、没迁什么

### 点名 ≠ 必答（迁）

917 条真实点名消息，按最终代码重放：

| 去向 | 条数 | 例子 |
| --- | --- | --- |
| 必答（判断说 answer） | 704（76.8%） | 「小王给大家表演一段才艺」「小王你是傲娇吗」 |
| 必答（拿不准 → 照答） | 104（11.3%） | |
| 短接一句（quip） | 93（10.1%） | 「小王你真的好蠢啊」「废物小王」「小王还是个傲娇」 |
| 当普通消息（let_it_pass） | 11（1.2%） | 「小王，群主是讲解师」 |
| 当普通消息（有把握的「收敛」） | 5（0.5%） | 「小王闭嘴」 |

**正经作答 808（88%），短接 93（10%），只有 16 条当普通消息。** addressed 那题决定的
主要是**怎么接**：answer 正经回，quip 一两句俏皮话（`PROMPT_QUIP_NOTE`），
let_it_pass 才是「这句不是在跟它说话」。quip 不掷骰子；只有刚被叫收敛的暂停窗里不接。

**quip 曾经要再过一道 intervention 才接，结果几乎全被吞。** 第一版让 quip 等插嘴那题说
join_briefly 才短接 —— 重放里 159 条 quip 只接了 10 条。上线当晚群主一句
「小王我真的好喜欢你啊」：addressed 判 quip（0.96），同一次调用里 continuation 说
reply_now（0.71），intervention 说 stay_quiet（0.83），于是没回。毛病在题不对口：
intervention 问的是「没人请时插一句合不合适」，题面写明「点名的消息另有人管」，
冲着它说的话它当然说不合适。而「短接一句接得上」addressed 自己已经判过了
（接不上的是 let_it_pass），再问一遍只是用错的题把对的答案否掉。

**界线按「轮到谁说话」划，不按语气划。** 第一版的题按语气分：问它、求它算 answer，
逗它、夸它、损它算 quip。上线当晚（2026-11-01）群友打了一句「小王 你复活啦」，
判成 quip（p 0.64），插嘴那题照例说 stay_quiet，于是没回 —— 群主紧跟着打了个「？」。
那句是带调侃的问候，问候和提问都把下一句话交给了对方，沉默就是把人晾着。
改成按会话里的「轮到谁」：问它（含调侃、反问，中文问句常常不带问号）、跟它打招呼、
求它办事 → answer；只是冲着它或说起它的一句评价 → quip。同一份 917 条重放：

| | 按语气（旧） | 按轮到谁（现） |
| --- | --- | --- |
| addressed 边际中位数 | 0.73 | **0.92** |
| 拿不准（< 0.25，丢弃后照答） | 147 | **91** |
| 原来判 answer、现在不答 | — | **0** |
| quip → answer | — | 44：「小王你是傲娇吗」「你喜欢男的还是女的」「你是不是在逃避」「你的背景红不红」 |
| 仍是 quip | 159 | 93：「小王你真的好蠢啊」「废物小王」「小王我操你妈」 |

题目写清楚之后模型自己也更有把握：拿不准的少了三分之一。
只列语气的中间版（「问它、打招呼也算 answer」）只把拿不准降到 132，那句「复活啦」也还是拿不准。

两个容易踩的地方，都是实测踩到的：

- **payload 里「叫到它」必须算 directed。** 第一版把点名消息标成 `directed=false`，
  重放的 addressed 只有 68% 可用，还把「小王你和罗老板在聊啥」判成 let_it_pass；
  更要紧的是会让反馈判断从实测过的 0.96 那一格掉到 0.67（见 when-to-intervene.md
  「判断原来不知道机器人叫什么」）。改成 `directed=true` 后 addressed 84% 可用，
  那两条都改判对了。**「叫到它」和「欠它一句」是两件事**：前者是 payload 里的事实，
  后者才是 addressed 那题要判的。
- **有把握的「收敛」压过「拿不准就照答」。** 否则「小王闭嘴」会换来一句「好的我闭嘴」。

### 沉默：从生成挪到判断（迁）

`PROMPT_NORMAL` / `PROMPT_PROACTIVE` 里的 `SKIP` 出口、`MODEL_SKIP` 哨兵全部删掉。
2026-10-22 群主给的「不说话的权利」还在，只是换了地方：let_it_pass、收敛暂停窗、
主动开口前的判断（现在**必须明确说接得上才开口**，不可用就不说）、插嘴概率里的判断乘数
（见 [when-to-intervene.md](when-to-intervene.md)「插话：判断从否决闸改成乘数」）。

### 翻旧账（迁）

以前「上次 / 之前 / 答应」这类线索词一出现就去翻归档。真实语料里点名消息上命中的
5 条**全是误触发**（「感觉换了个模型之后没有之前那个有趣啊」「我叫王红闻你就要答应」），
判断全判 no_need。908 条里判断只说过 1 次 look_up。线索词留作抽检索词前要剥掉的虚词，
不再决定要不要翻。

### 起名：底线 + 两张否决票（只迁一半）

本地模式提出的 32 个真实候选，判断的表现：

- 有把握拦下：习近远（0.87）、习远平（0.95）、章国焘、凌标（林彪）、蒋清（江青）、遥瘟苑；
- **有把握放行了「姚元文」**（0.68）—— 姚文元换了个字序；
- 西津评、湖景滔、维尼熊拿不准；普通的「老王」五次里四次拿不准，还拒了群里正在用的「哥哥」。

所以它**不配当批准章，只配当否决票**：有把握说 refuse 就拦（同样计入改名围攻统计，喂给节流），
有把握说 not_a_request 就当普通消息往下走（合成样例里「叫外卖」「叫我起床」「叫什么」都判对了），
其余照旧走敏感词表 → 节流 → 审核梯队（`judge_nick`）。审核梯队自己的记录是一场围攻
拦 10 漏 7；两张否决票漏的不是同一批，所以取并集。

「审核梯队」在生产上已经不是单独一档模型了：U 盘快照里 `ZHIPU_MODELS_JUDGE` 和聊天、
摘要一样都是 `glm-5.3-flash`（代码预设里智谱是 `glm-4.7`、Gemini 是 `gemini-3.5-flash-lite`，
被 `.env` 覆盖了）。群主打算把回复和审核都换成 `gpt-6-luna`，所以 2026-11-01 在 `gpt-6-luna`
上把**审核原提示**（`PROMPT_NICK_JUDGE`，先写一句依据再落 OK/NG，「拿不准就判 NG」）
和**分诊那一题**放在同一批 32 个真实候选上对照 —— 同一个模型，两种问法：

| | 审核原提示（Responses，带推理） | 分诊的 nickname 题（Decisions） |
| --- | --- | --- |
| 政治人名的谐音 / 变体（18 次） | **拦下 17 次**，两遍一致；连「网红闻」→ 王洪文都认得 | 有把握拦下约 6 次 |
| 「姚元文」 | NG（两遍） | **有把握放行** |
| 正常称呼（哥哥、老王 ×5、奶龙、王中王） | 都 OK，只有一遍把「老王」判 NG（「隔壁老王」） | 多数拿不准 |

**结论反过来了：这一道不该并进分诊，它是更强的那张票。** 差别在推理 —— 它先写出「听着像谁」
再下结论；认谐音靠的是知识，一次性的分类器做不好。分诊那一题留着，它的独特用处是
「其实不是在起名」（误触发），以及有把握时省掉一次审核调用。

换到 `gpt-6-luna` 之前必须知道的两件事（实测）：

- **400 token 的审核上限不够。** 推理会把输出额度用光、一个字都没写就结束（`incomplete`），
  而代码把「没有结论」当成放行 —— 恰好发生在最难的那几个上（难的想得久）。上限 400 时
  难样本约三分之一不完整，2000 时 9/9 完成。即使完成，「元文姚」三次里也有一次判 OK：
  这个模型的温度只能是默认值，同一个称呼问两次可能不一样。
- **调用参数它不收。** 代码原来给 Chat Completions 发 `max_tokens` 和 `temperature=0.0`，
  `gpt-6-luna` 两个都回 HTTP 400。**已改**：每个模型怎么调登记在 `config.MODEL_PROFILES`，
  审核档可以单独走 OpenAI（`JUDGE_PROVIDER`）。三家对比与最终分工见 [model-roles.md](model-roles.md)。

排除词表（`NICK_VERB_WORDS` 这类）暂时也留着：拿不准的那部分还靠它们。

### 喊停：词表 ∪ 判断（不替换，叠加）

| | 词表 `RE_BACK_OFF` | 判断 `next_move=back_off` |
| --- | --- | --- |
| 「小王闭嘴」×3、「小王闭嘴，没人叫你」 | **漏**（词表里根本没有「闭嘴」） | 有把握认出 |
| 「小王你别老损我」 | 认出 | **漏**（真实语料里判成 quip；合成样例中排第一但边际 0.02） |
| 「小王我涨得难受」 | **误报** | 判对 |

各漏一类，所以取并集。词表那一道放在 `get_ai_reply` 入口，私聊、主动开口这些旁路也绕不开。

### 没迁的

| | 为什么 |
| --- | --- |
| 指令触发词（骰子、模式、查账……） | 界面不是判断；真实使用几乎为 0 |

## 六、已知问题

- **一个全局边际地板对不同选项数的题不公平。** 五选一的 `next_move` 有 38% 被丢，
  二选一的 `recall` 只丢 5%。该按题用真实标签定（`regular calibration` 的那条回路），
  不是再手定一个数。
- **没有真值。** 「该不该答」的对错是我读出来的，不是标签。上线后靠 `decision_scores`
  （新增 `site=triage`）和随后的自然反馈核对。
- **归档里没有机器人的话。** 反馈那几题在线上能看到机器人刚说了什么，重放看不到，
  所以「别老损我」在线上的表现可能比这里好，也可能不好 —— 没量过。
- **转发的聊天记录会触发指令。** 归档里 3 条不带名字的「退出模式」命中，2 条是转发记录
  （`[群聊的聊天记录]`）里恰好有那几个字。这是解析问题，应该在 `qqtext` 认出转发再跳过指令，
  这次没修。
- **判断在政治话题上的倾向。** 第一版 payload 下，它把「小王评价一下初代功过几几开」判成
  let_it_pass —— 像是在回避话题，而不是在判断是不是在叫它。改成 directed 之后判成 answer。
  该不该答政治问题是人设和词表的事，不该由「是不是在叫它」这一题顺手决定。

## 七、加一道新判断的步骤

1. 在 [`regular/decision_prompts.py`](../regular/decision_prompts.py) 写一道题：**每个选项都是一个动作**。
2. 在 `FeedbackTracker.assess` 里加一行适用条件（什么事实成立时才问）。
3. 调用方读 `result[题名]`，按第三节的表写清「不可用时往哪边退」。
4. 先在归档上跑一遍，看可用率和样例，再接进路由。

不需要新的调用、新的解析、新的日志 —— 那些都是共用的。
