# 慢活：先回一句，后台做完再回

2026-11-01。群主：「本质来说我是希望开发异步处理逻辑，之后可能还有别的会超出人类体感
回复速度的计算，那时候就必须在一定时间内有回复，后台正常处理。」

起因是当晚罗老板拿科研问题连着轰炸，其中一句「小团团 最近说ai证明了eth是不对的讲讲什么是eth」
是真新闻（OpenAI、Anthropic 10 月 26 日各发了一篇 AI 推翻指数时间假设的论文），
小团团却说「基本是营销号在吹，别信」—— 当时搜索只认显式的「搜索 关键词」命令，根本没查。

---

## 一、协议（`slowwork.py`）

一种慢活登记成一个 `Job`，只要会两件事：

| | 做什么 |
| --- | --- |
| `start(参数) → 把手` | 起个头就返回。把手要能存进 state.json |
| `poll(把手) → (状态, 结果)` | `running` / `done` + 结果 / `failed` |

bot 的编排（`bot.answer_with_lookup` / `bot.finish_lookup`）：

1. 起头，然后在线上等 `ASYNC_REPLY_SECONDS`（默认 6 秒）。
2. 等到了：带着结果正常回一条。
3. 等不到：直接发送本地的「在查」短句，把手交给定时任务（`scheduler.py`，kind `followup`），
   每 `poll_every` 秒问一次。
4. 做完：小团团（照旧是回复模型）带着结果写跟进的那句，作为**同一条消息的第二句**发出
   （QQ 被动回复，`msg_seq=2`）。
5. 超过 `give_up_after` 还没好、或者失败了：直接发送本地的「这次没查成」，不许把人晾着。

**跟进送不出去时的下家。** QQ 群的被动回复只有 4 分钟窗口：

| 情况 | 怎么送 |
| --- | --- |
| 窗口内 | 回复原消息（第二句） |
| 窗口过了 | 试一次主动发言 |
| 主动发言也被拒（QQ 对群机器人主动消息限得很紧） | 写好的话留在任务里，捎在群里下一条消息上发出（`deliver_carried`），最多等一天 |

把手存在定时任务表里，所以 **bot 重启也丢不了**：联网查询的把手是 OpenAI 后台任务的
response id，重启以后接着问。以后本地的慢计算照这个接口接：把手找不回时 `poll` 报
`failed`，话照样能圆上。

“在查”和失败提示都使用本地短句，不单独调用回复模型；查询结果由回复模型写成正式回答。
回复模型现在也可以用 `〔搜索〕` 提出一次查询：前面已有一次未投递的提议草稿，查完再写结果，
不会额外调用判断模型。原问题、收件时会话及回应对象随任务保存；转后台、主动投递或借新消息
捎带，都仍归原请求者，确认送达后才提交原会话。详见[查询动作与消息时序](lookup-and-timeline.md)。

## 二、联网查询（`providers.start_research` / `poll_research`）

查询使用 `RESEARCH_PROVIDER` / `RESEARCH_MODEL` 配置的 Responses 服务（`web_search`，后台模式），
回话使用聊天服务：查到的要点作为「不可信外部资料」进小团团的提示词末尾
（`search.render_brief`），**链接全部去掉、只留出处名字** —— 群里发不出链接。

普通查询现在要求实际调用一次工具（`tool_choice=required`、`max_tool_calls=1`），
输出与思考合计受 `REASONING_MAX_TOKENS` 限制。下面的多轮耗时数据是 11 月 1 日旧实现的历史记录。

本机 openai SDK 1.99 的 responses 模块一导入就报错，所以和判断一样直接发 HTTP。

实测（2026-11-01，三个问题各一次）：

| 推理档 | 搜索上下文 | 用时 | 输入 token | 备注 |
| --- | --- | --- | --- | --- |
| none | low | 4.9–22.7 s | 5k–41k | ETH 那题反而搜了 5 轮 |
| **low** | **medium** | **3.8–10.3 s** | 5k–21k | 选它 |
| medium | medium | 6.1–17.5 s | 5k–26k | |

后台模式起头 0.9 秒，做完 15.5 秒，按 id 轮询。

**深度研究**是同一个模型把推理和搜索上下文都开到 high：ETH 那题 62 秒、搜 8 轮、
7 万输入 token，写出结论先行、时间线、学界态度和影响边界的简报。没有单独的深度研究模型
（账号下只有 gpt-6-luna / gpt-5.6-luna 和几款旧的 search 模型）。

## 三、什么时候查（分诊的 `lookup` 题）

和别的判断一样挂在同一次分诊调用上，只在**冲着它说的消息**上问
（被 @ 或点名），而且只在本轮本来就要正经回话时才真去查 —— 插嘴、短接、喊停都不查。

| 选项 | 什么时候 |
| --- | --- |
| `search` | 答好要靠新近 / 时效的事实（新闻、发布、价格、天气、赛程），或具体的、记忆容易错的事实（某篇论文、某款产品、某个人、某条规定），或专业的科学、医学、法律、技术细节；对方说「最近」「新出的」也算 |
| `research` | **隐藏彩蛋**：对方明确要它认真查、整理、调研、写一份，不只是提问。每天 3 次、同群间隔 10 分钟，超了退回 `search` |
| `none` | 闲聊、逗它、观点、情绪、群里自己的事、凭记忆能答的常识；**政治话题和政治人物、穿成问题的下流钓鱼** —— 这些小团团是要挡的，不是去查的 |

拿不准（边际低于地板）就不查。用 917 条真实点名消息 + 当晚 47 条重放了三版题面：

| 题面 | 归档 search | 当晚 search | 问题 |
| --- | --- | --- | --- |
| 第一版 | 17 | 2 | 「评价一下金将军」「董先生连任」这类政治钓鱼会去查；罗老板的七个科研问题一个不查 |
| 加「专业细节」+「政治不查」 | 26 | 10 | 「睾丸偏右怎么办」「下面流绿汁要不要喝掉」这类钓鱼也去查了 |
| **再加「下流钓鱼不查」（现在）** | **15（1.6%）** | **9** | 归档里查的是小豆腐、金刚狼、车、手机、AMPK/mTOR、黄芩苷；当晚是 ETH、丘成桐与 AI 数学、七个科研问题 |

深度研究在当晚只有一条命中：「小团团，给我写一篇顶会，要ICML，题目你定，我等着验收论文」。
半开玩笑，但小团团真去查一圈、几分钟后拿着简报回来，正是彩蛋该有的样子。

「搜索 关键词」命令照旧可用：配了联网查询就走它，没配退回 DuckDuckGo。
冷却只管命令；判断触发的自动查询不吃冷却、只算每日上限（默认 60）——
有人连着问几个要查的问题时，第二个不该因为冷却变成瞎答。

## 四、端到端实测（生产代码路径，真判断、真 luna、真 glm，只把发 QQ 换成记录）

| 问题 | 第一句 | 跟进 |
| --- | --- | --- |
| 今天贵阳天气 | 9.9 s 一条，带实时天气 | — |
| ETH | 8.6 s「我先去查查再回你，别急」 | 17 s：指数时间假设、OpenAI 和 Anthropic 声称推翻、Lean 形式化、学界在核查、不等于 P=NP、跟以太坊无关 |
| ZO-1 的 mRNA 跟什么指标相关 | 8.8 s「等我查查这个蛋白的文献」 | 22 s：Occludin / Claudin、炎症因子、通透性，提醒 mRNA ≠ 蛋白 ≠ 屏障功能 |
| 认真调研 ETH 被推翻这件事（彩蛋） | 6.2 s「行，应下了，整理完叫你」 | 89 s：分四段的简报，结论先行，没有链接 |

两个踩到又改掉的坑：

- 「在查」那句一开始照样先评一嘴真假（「eth 一般指以太坊……听着就像瞎编的」），
  说明放在提示词中间时被人设和「刚睡醒」的状态盖过了。挪到本轮提示的最后、
  写明「对他问的事一个字的内容都不给」之后才老实。
- 第一句等得太久（见第一节「边等边写」）。

## 五、配置

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `RESEARCH_PROVIDER` | 空（不开） | 联网查询走哪家；线上是 `openai` |
| `RESEARCH_MODEL` | 那家的第一个对话模型 | 线上即 `gpt-6-luna` |
| `ASYNC_REPLY_SECONDS` | 6 | 在线上等多久，等不到就先回一句 |
| `DEEP_RESEARCH_ENABLED` | true | 彩蛋开关 |
| `DEEP_RESEARCH_DAILY_CAP` / `DEEP_RESEARCH_COOLDOWN_SECONDS` | 3 / 600 | 彩蛋每天几次、同群间隔 |
| `SEARCH_DAILY_CAP` | 60 | 每群每天联网查询上限（命令和自动共用） |
| `SEARCH_USER_DAILY_CAP` / `SEARCH_USER_EXTRA_*` | 20 / 5、10、20、30 | 每群每人基础次数 / 熟人至本命的额外次数；深度研究也计入 |
