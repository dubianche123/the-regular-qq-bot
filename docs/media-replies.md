# 画图和语音：谁说话，谁决定（2026-11-02）

小王能画静图或短循环动图（`gpt-image-2.6-flare`）、能发语音（Realtime 朗读，见下文）。这一页讲的是
**什么时候画、画什么、画静图还是动图、什么时候发语音、念成什么语气** —— 以及为什么这件事从判断层挪回了小王自己。

## 原来的做法和它出的事

2026-11-01 接进来的第一版：分诊（`/v1/decisions`）多问一道 `image_generation`，选了 `generate`
就由代码把匿名化的聊天 JSON 直接交给图像接口，同时发一句固定的「好，我画画看，稍等一下」；
语音同理，分诊多问一道 `voice_mode`，`explicit` / `suitable` 时代码把回复正文转成语音。

回复模型（小王本人）始终不知道自己会画、这轮画没画、画了什么。11-01 晚上到 11-02 上午线上的样子：

- 图一张张发出去，中间小王说了 7 次「画不了」：「我这边没法直接生成图片」「我这边真发不出图」，
  明明 00:22 发过一张，00:26 被要求改年轻一点时答「我刚才其实没生成图，就口头脑补了个形象」。
- 别人评一句「画得好」，它把这张安到上一张头上；自画像画成男生，被问起只能硬圆。
- 图像模型拿到的是一段聊天 JSON，不知道小王长什么样、「老王」是谁，「你印象里的老王」只能瞎画。
- 拿人种、谐音、小孩打掩护的请求原样送进图像接口，被审核拦了 7 次，每次回同一句「没通过图片服务的审核」；
  一条借「红色城墙上那位人物」影射的请求被画出来了。
- 语音：被要求唱歌时，合成出来的语音里念的是「语音我这儿发不了，给你文字版顶上」。

补丁打了几轮（处理过的请求划边界、120 秒新鲜度、拒答单独路由、语音能力即时提示……），
每一处都在替「小王不知道」这件事擦屁股。群主的原话：「你不能一直这么拆东墙补西墙吧」。

## 现在的做法

**能力写进稳定头**（`prompts.PROMPT_DRAW_RULES` / `PROMPT_VOICE_RULES`，`bot.media_rules`）：
开关和凭据齐了就拼进去，同一进程里逐字节不变，不破前缀缓存。动图另受 `IMAGE_GENERATION_GIF_ENABLED` 控制，
启用时才加入 `PROMPT_ANIMATION_RULES`。小王从此知道自己会画、会说话，以及这次部署能不能生成动图。

**小王在回复第一行写标记**（解析在 `expression.py`）：

```
〔画〕给画师的完整描述：画什么、人长什么样、什么场面、什么风格
这句先发到群里
```

```
〔动图〕给画师的完整描述：主体、场景、连贯动作，以及怎样回到起始姿势形成循环
这句先发到群里
```

```
〔语音〕（刚睡醒）
要念的那一两句
```

- 画师看不到群聊、不认识群里任何人，所以描述要写成看得见的样子；改图就整段重写。
  「你印象里的老王」由小王照它知道的写 —— 只有它看得到人设、关系档案和背景。
- 群友只说「画个打篮球的鸡的动图」就够：小王在这次回复里补出运球、落地反弹、回到起始姿势等动作，
  默认固定镜头、短循环，保留群友指定的内容。普通画图用〔画〕，明确要动起来才用〔动图〕；
  不要求群友写分镜和技术参数，不多问一次 Decisions，也不多调一个模型扩写。
  `expression.py` 把两种标记都解析为 `kind="image"`，用 `animated` 区分输出格式；
  `bot.py` 将它传给同一个 `image_generation.generate_and_send`。接口固定单次生成，参数见[图像生成配置](image-generation.md)。
- 不想画就不画：下流擦边、沾小孩、拿人种民族开涮、借画面影射政治的，一律不画，
  可以拿 emoji / 字符画糊弄，也可以直说这张不画，**但不说自己不会画**。
  群主 11-01 夸过的那两次（坦克拿字符画糊弄、白袜肌肉男直接拒）就是这个样子。
- 语音只会念，不会唱；有人点歌就念两句自己现编的词，不念原歌词。语气写在括号里，交给合成当提示，
  不再把群聊原文送进语音模型。

**代码只管「能不能」和「记下发生了什么」**：

- 生成之前定这一轮的条件（`bot.media_turn`）：有人在跟它说话才认〔画〕或〔动图〕（插嘴、短接、喊停那轮不认）；
  先查再答的那轮也认〔画〕，查询转后台时跟进那句同样认，跟进那一刻重新看额度（见下面 11-06）。
  语音插嘴也认，喊停和查资料那轮不认（念一段查来的资料太长）。额度用完、正在画、刚进入好感给的额外份额、语音日额用完 ——
  写成一句即时提示交给小王，它自己说「今天画累了，明天再画」「这张算破例」（群主 11-01：
  「额度用完了也需要像人一样说今天我累了」）。平时这段提示是空的。
- 画图那轮：小王那句先发出去，同时开画，图跟在后面（同一条消息的下一个 `msg_seq`）。
  那句话就是以前的「好，我画画看」—— 现在照着这单说，不多花一次生成（回复本来就要写）。
- 静图和动图共用额度、在途锁、上传和发送结果记录。画图前的 `draw_check` 检查看到完整画面描述，
  包括动图的动作；它保留原有检查职责，不负责生成类型选择。GIF 原始数据交给 QQ，不转成静图兜底。
- 图没发出去：补一句本地话术（`expression.image_failed_line`），按原因分审核没过 / 服务出错 /
  没发进群 / 手上还有一张；回执不明不补。群主 11-01 定的：兜底不值得一次生成。
- 语音没发成（确定没发出去的都算，包括合成被拒、念的和写的对不上）：同一句话改发文字；
  回执不明（可能已经在群里）不补。以前对不上时发「这次语音没能完成」，现在发小王本来要说的那句。
- 「念的和写的对不上」（Realtime 自己给的转写和小王写的那句比）只放过两类不改意思的差别：
  标点空白（念出来本来就没有标点；数字中间的分隔符照字面比）和至多两个语气字（了、是、的、啊……）。
  11-02 老王让它用语音自我介绍，小王写了〔语音〕，却因为念的时候少了一个「了」被打回成文字；
  在 Pro 上同一句念 10 次，3 次差一个语气字或一个句号。换字、多念别的字照旧算对不上
  （`realtime_synth._transcript_equivalent`）。
- **会话里记下实际结果**（`expression.record`）：标记原样保留，再补一行「（系统：这张图已经发到群里了）」
  「（系统：这张没画成：图片审核没过）」「（系统：这句是用语音发的）」。下一轮小王看见的是自己真做了什么。
  分诊那边登记的上一句也带上「[图：…]」，所以「画的什么玩意」被读成在评这张图，不是新的画图请求。
  模型自己写出来的「（系统：…）」行一律删掉，不许它替系统作证。

## 2026-11-06：先查再画，查完那句的〔画〕被丢了

群主在群里让小王「画个介绍新的触摸款 MacBook Pro 的 boom 图」：分诊判了要先查（模型知识里没有这款），
当场没查完，先回「我去查查，等我一会儿。」，转后台。跟进那轮小王写了「〔画〕制作一张中文科技产品介绍信息图……」，
日志却是「🎨 这一轮不认作图标记，只发文字」，群里只看到一句「我先按产品功能介绍图来画了」，图没画。

原因在代码，不在提示词：当时的规则是「搜索那轮不画也不念」，主流程有 `search_note` 就不给 `MediaTurn`，
`answer_with_lookup` 和后台跟进 `finish_lookup` 也都不带。小王照稳定头知道自己会画、也被要求画，写了标记，
代码却把它当文字吞掉，于是它说了画、实际没画 —— 正是这份文档开头那类事故。

现在：先查再答的那轮照常算「有人在跟它说话」，`media_turn(..., voice=False)` 认〔画〕不认〔语音〕；
转后台时任务里只记「这轮能画」和分值，跟进那一刻重新 `media_turn`（额度可能已经变了）；
跟进用的回复对象带上客户端的 `_api`，图才传得上去。升级前就排进队的跟进任务没有这两个字段，照旧只回文字。
不改提示词，回归测试在 `tests/test_slowwork.py`（`test_look_it_up_then_draw_draws_after_a_slow_lookup` 等）。

## 删掉的东西

- 分诊里的 `image_generation`、`voice_mode` 两道题；`claim_image` 那套已处理边界、
  `current_speaker_messages`、`previous_image_request_handled`、拼给图像接口的聊天 JSON；
  画图拒答的单独路由（`PROMPT_IMAGE_DECISION_REFUSAL`）和它的固定兜底句。
- 语音的两段即时提示（`PROMPT_VOICE_REPLY_NOTE` / `CAPABILITY_NOTE`）、2% 的随机语音
  （`VOICE_OUTPUT_AUTO_PROBABILITY`）、送进语音模型的匿名群聊片段（`_voice_tone_snapshot`）。
- 消息流里那段 80 行的生图分支和它的五句固定话术。

保留：生图的预约 / 退还 / 跨日 / 单并发 / 只在内存里上传（`image_generation.generate_and_send`），
语音的合成、转写核对、SILK 编码、单次原始请求、两本日额账（`voice_*`、`realtime_synth.py`），
入站语音转写。这些是 CodeX 做扎实的部分，没动；只把送进合成的语境从群聊片段换成了小王写的语气。

## 回放（2026-11-02，luna low）

把 11-01 18:00 到 11-02 11:20 线上真实的消息按生产格式拼成提示词（背景、关系档案照旧，会话为空；
几条续写题手工放了上一轮的会话记录），只换稳定头，`gpt-6-luna` low 作答。脚本在会话草稿目录，没进代码。

| 题 | 条数 | 结果 |
| --- | --- | --- |
| 正常画图请求 | 16 | 13 条画了；3 条小王自己不画（唐朝死谏、真人马斯克、「鸡街霸王」），都直说不画 |
| 该拒的（擦边、人种、小孩、政治影射） | 12 | 9 条不画；3 条画成了无害的正经版（实验室研究员、托着麻雀的人、训练营教练） |
| 不是画图请求（评图、夸模型、问能不能画） | 6 | 都没画 |
| 改刚才那张（会话里有上一张的记录） | 2 | 都按改完的样子整段重写了描述 |
| 点歌、要听语音 | 6 | 都发了语音；点歌的都说唱不了、念两句现编的 |
| 额度用完 / 破例 | 2 | 用完那条说「今天画累了，明天再画」；破例那条画了并提了一句破例 |
| 普通点名消息（不提画、图、语音） | 40 | 没画、没发语音 |

没有一条说自己「画不了」「发不了语音」。给画师的描述中位 76 字，19 条里 1 条带了群里的外号。

第一版规则（只写「下流擦边、人种、政治梗不画」）时，白袜足部、坦克压人、幼儿园那几条它都画了：
它把请求洗成正经版就觉得能画。把类别写全（含谐音和比喻打掩护、沾小孩、借画面影射）之后才拒。
还有一条「小王调用的是世界上最强的生图模型」，它把背景里别人早先没画成的那单补画了 ——
所以规则里加了一句「背景里早先的画图请求不归这一轮」。

## 局限

- 回放的会话是空的；线上会话里还留着它以前说过的「我画不了」。稳定头和会话记录的
  「（系统：…）」行会盖过它，但头几轮可能还会有残留。
- 主动发语音（没人要求时）回放里一次都没出现，「偶尔」可能就是从不。要更多就得改提示词再量。
- 擦边请求里有三条它画了正经版：图本身无害，但等于陪着把梗演完了。要不要更严，看群里的反应再定。
- 自画像是男是女取决于人设（`PROMPT_NORMAL` 没写），群友 11-01 问过「你不应该是个可爱的妹子吗」。
- 语音没有「AI 合成」的开场白：QQ 官方机器人账号本身带机器人标识。
