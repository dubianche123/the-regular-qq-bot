原生桌宠按需解码 WebP 动作条，并维护有上限的近期缓存。它用本机状态安排日常、心情和作息变化；图片和动作选择本身不调用模型。小球、金币和宝石是可拖动、可归还的临时道具，最多同时两个；星光和羽毛等是几秒便淡出的鼠标透传特效，不会写进 QQ 账本。

## 从动作数量改为节目选择

旧库中很多动作只有站姿和道具不同。常规陪伴按大类保留少量有区别的代表，优先照顾身体、姿势和观看感受的差异：乐器保留不同弹奏姿态，玩具区分掌机与观察，阅读和茶保留能长驻的小动作。睡姿、手机等不再为了展示库存轮番换皮；真实忙碌、飞行、藏边、落地仍用它们需要的完整状态和过渡。

日常分成三种用途：

- **长驻陪伴**：同一件事持续一段时间，例如看漫画、玩掌机、擦宝石。小结果在活动之后出现一次，与活动一起被打断或取消。
- **生活流程**：旧 `STORIES` 中烧水、倒水、吹凉、喝水一类程序性组合，在完整剧场素材可用时不再占它的抽选槽；只为缺少新素材的旧资源保留回退。用得上的动作留作活动或结果，不把按顺序做事本身叫作故事。
- **完整剧场**：选择本身有变化和结果，例如偷咬后多分一半、喷火成功或失手。自动触发仍需距上次至少 180 秒、经过两次长驻，再以 45% 概率进入；保留原节奏，提高每次抽到的内容质量。

`activity_sequence` 把主活动和结果放在同一个可打断计划里，按本机心情、精力选择，并避开近期结果。素材不足时保留原活动，不拼接缺拍的故事。完整剧场和活动结尾都根据已经播出的结果片段去重；被打断、尚未播放的结尾不算已看过。去重不要求更频繁地演出。

## 性格怎样变成行为

[角色设定](character.md)仍以矛盾组织性格，但结局包括成功、失落、温柔和发现。现有素材能支持以下变化：

- 游戏会赢、惜败或重赛；困意和心情影响选择，重赛仍可能输。一次失落可以就此结束，不必补一个胜利或装没事。
- 自己的魔法画布会亮出成品、专心返工或发现脸上沾了颜料；结果只演一次，不在已经亮画之后再重复展示。
- 阅读长驻有自己的结果，例如读到有趣处或收好书；收藏也会从把玩、擦亮转向分享。选片保持同一件物品，不把硬币、宝石、纸星和纸鹤混成一件东西。
- 茶可能刚好，也可能急着喝被烫到；后者会先吹凉、再试喝，最后放松。喷火可以控制得恰到好处，也可能过猛吓退后扑灭；成功不再附加自嘲。
- 甜点可以主动分一半，也可以偷偷咬一口后多分给你。补偿分支用 `scene_sweet_sneak → scene_sweet_share_more`，不在已经递出后又倒回偷咬。
- 椅子和沙发按进场、长驻、收起连成一段。长驻恢复一点能量；用户换节目时先收场，自主追球不会把家具演出拦腰切断。
- 变小龙是稀有的惊喜：一团云盖住切换，小龙蹦跶几步，试飞摔趴、爪子拆不开糖、圈住宝物打盹或追尾巴转晕，再变回人形。只有拆糖分支检查手心的糖，其他分支只整理头发，不凭空变出糖果。被戳、被拎起或群里有事时，同样一团云马上变回来。
- 她会贴近无形玻璃看你、擦开一小团雾，或发现日记被看到后合上抱住。扑光标按落点与真实指针距离区分抓到和扑空，扑空装伸懒腰仍是保留的一种笑话。

2026-11-08 继续补画了角色设定中缺少的身体选择：抱书安心睡、把最后一块完整饼干放下、护住小灯、吹凉第二杯、翻旧收藏出神、收回招呼留空位、宝石舍不得到松手、先确认观众再准备、把画留作礼物，以及困了放下掌机。欣喜、低落、好奇和安静陪伴也各有重心、手、翅膀或尾巴的变化。新书、双杯、宝石和画作的小戏各自在同一张四帧里完成，避免把不同旧道具硬接在一起。采用、触发和验收明细见[本轮演出记录](pet-performance-2026-11-08.md)。

小剧场没有单独的菜单入口，只在日常里自然发生，「换个节目」也可能抽到。投喂固定为期待、接过、认真吃、满足回应，四拍来自同一张 `daily_cookie_receive`；延迟回执不会让她再吃一遍。主动分享另属甜食日常。被摸头后偶尔露一手（小火苗或变小龙试飞）。家具约半小时出现一次，小龙两次至少隔二十五分钟、启动十分钟内不变。同一活动的入场和结果都只演一遍；循环只用于中间的安静陪伴。单次场景按「起势稍停、中间连贯、结果稍留」播放，播完接下一拍。这里的游戏、作画是本机日常，群里真实作画、搜索和回复仍跟随实际进度。

新增小戏沿用完整剧场的冷却和两次长驻门槛，不另开高频入口。抱书入睡只在困时出现，接同源末两帧停留 35–60 秒；放下掌机在困时或精力低于 0.5 时可选；欣喜和低落分别要求本机心情至少 0.2、至多 −0.2。安静陪伴坐姿作为长驻停留 45–90 秒。看向观众、收回招呼是写好的演出，不检查用户正在看什么，也不新增模型判断。

长驻活动期间也会低频检查附近已经落地的道具，避免活动还没结束，道具就先消失。靠近、拖动或收起道具都会重新核对目标；真实工作、睡眠和本机互动优先。此前三个日间种子各模拟一小时，已观察到主动踢球和拾取成功。

## 法术与特技

旧道具库的大量动作是「站着拿一件小东西，只动手和眼睛」，这正是本轮收窄默认池的原因。法术组已经采用整段动作：
每张图都是一段完整表演（预备、动作、余势、收势），位移、法阵和「沉进阵里」的裁切由程序逐拍调度，
所以画面里不画地板、洞、法阵、光效。参照的是成熟开源桌宠的做法：

- [VPet-Simulator](https://github.com/LorisYounger/VPet/blob/main/VPet-Simulator.Core/Graph/GraphInfo.cs) 把每个状态拆成开始、循环、结束三段。群里在画图时，她先变出画布，再循环作画，
  图发出去时把画布转过来给你看；查资料时先召来魔法书，翻书，答完指一下「找到了」。
- Shimeji、eSheep 把整块屏幕当场景，并且偶尔来一段很少见的大场面。传送就是这种大场面：
  她抬手在脚下画出旋转的符文阵，目的地同时亮起第二个阵，她起跳、捏着鼻子「冰棍跳」沉进去，
  再从远处的阵里举着手冒出来，摆个「噔噔」落地。有时目的地是菜单栏下的天花板，她从上面掉下来。
- Neko、Desktop Goose 会追光标。光标在她面前来回晃，她会伏低、晃屁股、扑过去，用手捧住。

| 节目 | 何时出现 |
| --- | --- |
| 传送 `warp_*` | 日常偶尔选中（至少隔 75 秒）；「更多 → 变个魔法」；被戳烦了偶尔开阵溜走；被 @ 且光标离她很远时，传送到光标下面再看消息 |
| 打喷嚏 `sneeze` | 日常偶尔、刚睡醒时多一些；喷出一小团火和烟，少数时候阵会意外打开，她掉进去、从天上掉下来，一脸懵 |
| 魔法画布 `conjure` → `paint` → `paint_reveal` | 小团团在群里画图的整个过程；图送达时亮画 |
| 魔法书 `tome` → `tome_found` | 小团团转后台查资料时；面板心跳先报「看图」也会换成魔法书 |
| 扑光标 `pounce_*` | 光标在她身前一到两个半身位来回晃，至少隔 20 秒 |

施法那一拍仍是普通的地面动作：期间来了群聊事件、点击、拖拽或面板指令，阵会合上，她直接去做新的事。
一旦起跳就不能被拎走，新的动作排在落地之后。屏幕太窄、关闭动作和特效、或者用的是没有这组素材的旧资源，
她就只做个小手势，不传送。法阵是两个点击穿透的小窗口：远半边和地面光晕在她身后，近半边、光柱余晖和上升的光点在她前面；
窗口不会要求放到菜单栏之上（macOS 会把它挤下来）。

## 高频动作怎样变化

素材中仍保留 12 组睡姿，默认只选有明确姿势区别的代表；打盹有间隔，不因库存多而增加频率。回复按开心、安静、斟酌和困倦等状态选择合适姿态，不把相似手机动作当成节目数量。心情好、精神足而且没有打开聊天面板时，她可以飞着回 QQ 消息；困了则坐着慢慢回。打开聊天面板时，她留在旁边回复。本机文字聊天也使用这套回复动作。

看图、听语音、查资料、画图和发语音各有对应动作池，持续到真实工作结束，再回到日常。正在忙的状态优先于随机节目，拖动、点击或聊天打断后仍能接着忙。

## 验证与已有修复

验证分为已有素材的编排修复和新素材的实际播放。检查活动与结果连续、近期去重、安静模式和打断，并以实际桌宠尺寸观看所选素材。测试和长时间模拟用于发现卡住、重放、选错素材或演出过密，不能证明演出有趣；可爱、节奏和耐看程度仍需看完整播放并反复观看。

2026-11-08 用相同的日间合成条件、种子 3／7／19 各跑一小时：长驻时间均值由 60.53% 到 62.10%，三小时故事选择由 19 次到 15 次，家具由 8 次到 4 次；原先单次动画被误排成长驻造成的 187 秒额外定格降为 0。护宝末尾两三秒睡熟停留单独计为有意停留。椅子和沙发的自动入口共用 1800 秒冷却。另用实际 Qt 渲染完整检查甜食补偿、惜败放下、喝茶放松、宝石分享和护宝变回人形五段，程序缩放始终为 1，未额外放大缩小人物。

此前素材建设与修复：2026-11-07 首批动作库扩展有 253 次成功生图、采用 232 组；后续边缘过渡补画 6 次、采用 4 组，又重画并替换 5 组扑翼和空中回复。加上 8 组法术表演、2026-11-08 的 9 组边缘动作、34 组角色场景和 7 组小龙形态，扩展前清单为 337 条。本轮增加日常与边缘新片段，最终清单和验证结果另见[本轮演出记录](pet-performance-2026-11-08.md)。动作调度、四边隐藏与点击出场、心情与回复、睡姿、道具、素材构建及本机面板均有对应离线回归。

本轮六段日常用 macOS Cocoa 原生窗口、真实时钟连续录制，每段 10 秒；画面只抓取验收进程自己的 Qt 窗口，并按实际原生窗口位置合成，不截取其他应用、不连接服务。覆盖投喂的延迟回执、抱书睡的同源停留、护灯、抱尾巴自我安慰、欣喜和留空位。四边清醒微动作各录 16 秒，眼神、支撑和出口观看通过，动态锚点误差小于 0.5 像素；四边另录睡醒，已确认固定支撑、逆序醒来和顶部全部转身帧；气泡改用实际 alpha 轮廓与绘制变换避让，修复后四边各重录 16 秒，头发、角和眼睛均无遮挡，最后全部回到地面。此前相关桌宠测试为 280 passed、939 subtests passed，最终气泡修正后单独重跑 Qt 文件为 56 passed、62 subtests passed；记录、命令和已有 Qt 退出警告详见[本轮演出记录](pet-performance-2026-11-08.md)。

原图缓存最多 8 组，缩放缓存最多 96 张且不超过 48 MiB；缓存会淘汰旧项。素材以对应形态的待机头部为基准统一比例（`tools/pet_sprites.py calibrate --source <原目录> --out <新目录>` 离线比对、输出 `calibration-report.json`，核对后再替换），512×512 的透明画布为举手和展翼留出空间。同一动作内需要时逐帧按头部校正；小龙动作以小龙设计稿的头为基准。2026-11-08 复核时，喷火过猛、日记、贴玻璃第一帧和侧边睡滑的头大了 1.2–1.3 倍，搬椅子、沙发入场、擦雾、扑空和扒边歪头差一成左右，已按脚底锚点（扒边动作按抓握点）逐帧缩回；自动测量对坐姿、低头、遮脸会误判，最终以并排图人工复核为准。家具入场、长驻和退场复用同源帧，保持同一件家具。播放时不叠加呼吸缩放、按压缩小和落地压扁；贴屏小戏有明确的靠近、透视和退开帧序。贴玻璃打招呼靠压扁的脸颊和姿势表现凑近，不再放大人物；网页会补偿透明留白。五张候选使用内置图像工具修复透明背景或布局，缩放保留预乘 alpha 的角色 RGB，未用自动 alpha 阈值抠图。

素材检查要区分真正的比例漂移与蹲下、展翼、举起道具造成的外轮廓变化。整幅透明边界的高度不能当作人物身高来逐帧校正。重画的五组扑翼已逐帧核对头身比例与翅膀角度；飞行上升和悬停使用循环扑翼，起飞准备与落地各自演完再转入下一段。

拖到屏幕任一边缘松手，她会把身体藏到边外，只留下头和必要的抓边手，直到点击或拖走再出来；鼠标靠近和群聊心跳不会让她自行离开。底边露头高度按实际素材计算，四边的不可见部分不占鼠标点击区域。顶部清醒与微动作的锚点在顶边下方 `0.45 × figure`，睡眠为 `0.38 × figure`；隐藏曝光不使用鞋尾挂点 `rest_y`，避免把整个倒挂身体拉进屏幕。

藏好后身体保持稳定，眼睛跟随鼠标左右看，间或眨眼，不把整段探头起落反复播放。首段边缘微动作在藏好 25–40 秒后才可出现，之后相隔 45–70 秒，入睡前四秒停止；安静模式或减弱动态时不演。侧边是尾巴招呼和侧耳听，底边是安静看你和哈欠，顶部是固定双手、眼神跟着绒羽。演完回到原来的探头，不重置入睡时间。

隐藏时有独立的打盹状态：底边枕着手臂或掏出小枕头趴睡；侧边沿用抓边姿势，`boundary_side_doze` 从 `motion_edge_look` 取 `[1, 1, 3]` 入睡，再以 `[3, 3]` 闭眼停留；顶部仍只露倒挂睡脸和枕边手，蜷起的身体藏在屏外。入睡只演一次，点击反播同源帧醒来。底边的手臂、枕头继续使用固定支撑坐标，不叠加整个窗口下滑；侧边保留松手高度。旧全身 `boundary_side_sleep` 以 `automatic=False` 留档，不再自动选中，也不自动睡滑。

点击先用同一睡图的入睡帧逆序醒来，再接蓄力、真实位移弧线、循环扑翼和落地。顶部主动离场的 `prepare` 阶段保持首格，用 0.4 秒从探头位置逐渐露身，此时才按 `rest_y` 对齐鞋尾支撑；接着胸前双掌开阵，确认路线后松脚、转身并沉入近端法阵，再从地面出口升出。普通传送落地后有 18% 概率踉跄、扶稳、站好，连续两次传送不会都踉跄；喷嚏传送不再追加这次失手。出场全程使用固定人物比例，减弱动态时快速回位。离开顶部时同时清除原生隐藏遮罩，避免残留形状裁掉人物。

## 维护素材

新增动作先写动机、变化与结局，再选道具。模板固定镜头和头身比例，允许全身重心、蹲伏、展翼和伸手变化，不再要求身体锚定不动、只移动手和道具。循环片段只承载可自然反复的小动作；单次片段保留后果，不强求第四帧回到第一帧。串接前核对姿势、物件和前后状态，缺连续素材时缩短或补画，不用台词掩盖。

法术组用 `--group spell` 生成。大幅动作容易把手或尾巴伸进相邻格子，`drop_strays` 会擦掉贴着格子边缘的小碎块；
蹲伏、俯冲时脸会被遮住或变形，`calibration_frames` 指定拿哪几帧和待机头部比大小（扑光标只用前两帧伏低的脸，
用错帧时整条会被放大到 1.5 倍）。生成两套候选、挑好的再 `build --only`，构建后用 `HeadMatcher` 逐帧复查头部比例。

`tools/pet_sprites.py` 使用原创角色定稿和已有动作表作为参考，原始动作表放在仓库外。先查看计划：

```bash
.venv/bin/python tools/pet_sprites.py generate \
  --directory ~/.the-regular --output /tmp/regular-pet-sheets \
  --stage library --group dragon --only dragon_fire_palm
```

计划只列请求和发送内容，不调用图片服务。实际生成需要在实例 `.env` 配置 `OPENAI_API_KEY`，并明确加 `--allow-paid`；需要的 `base.png` 和对应风格参考图应先放入输出目录。请求只发送原创角色参考和动作提示，不发送群聊。生成记录写入输出目录的 `requests.jsonl`；失败不会自动重试，已存在的成功图片会跳过。

候选先检查四帧的角色一致性、肢体、道具、透明度及裁切。`review` 可辅助检查布局、透明度和边缘，但不能代替人工看图：

```bash
.venv/bin/python tools/pet_sprites.py review \
  --source /tmp/regular-pet-sheets --out /tmp/regular-pet-review --group dragon
.venv/bin/python tools/pet_sprites.py build \
  --source /tmp/regular-pet-sheets --out /tmp/regular-pet-built --only dragon_fire_palm
```

`build` 离线按格子切帧、对齐并生成 WebP 与清单；检查结果及播放表现后再将选定素材纳入运行包。原始候选和请求账本不必进入仓库。动作库的日常调度由 `regular/pet_brain.py` 管理，道具计算在 `regular/pet_props.py`，原生窗口和按需加载在 `regular/desktop_pet.py`。
