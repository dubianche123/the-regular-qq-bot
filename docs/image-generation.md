# 群聊自然语言画图

画不画、画什么由小王自己在回复里决定：它在第一行写「〔画〕」加一段给画师的描述，代码才去画；判断层不再问画图题。小王那句话先发到群里，图跟在后面。规则、标记格式和为什么这么改，见 [画图和语音](media-replies.md)。

默认使用 OpenAI `gpt-image-2.5-flare`，`medium`、`1024x1024`，每群每人每天基础 5 次；关系达到熟人、好朋友、铁哥们、本命时，分别为 6、7、9、13 次。每天全局最多发起 40 次，因此多人同时使用时可能先碰到全局上限。请求前持久化预留个人和全局次数；确定没有发出图片时返还个人次数，已发出的 QQ 消息如果回执不明，则保留个人次数，避免把可能已送达的图片当作失败。全局尝试上限保守计入已发起的请求：接口超时、审核或 QQ 上传失败时上游费用未必为零，不自动重试。同一时刻只处理一个生图请求。图片只在内存中交给 QQ 上传，不写入文件。

第一次使用好感度带来的额外份额时，小王会说这次破例；额外份额本身仍有上限。额度用完它会说今天累了，明天再画。搜索同样按群友和关系档位单独限额，默认基础 20 次，四个关系档依次为 25、30、40、50 次，同时受每群搜索上限约束。额度在本地持久化，次日重置。

同一时刻只画一张：小王写回复之前就知道手上有没有一张没画完、这个人今天的额度还剩多少、这张是不是破例，用自己的话说出来。图没发出去时补一句本地话术，按原因分审核没过、服务出错、没发进群；回执不明不补。会话里记下这张画了什么、发没发出去。运行日志只记阶段、异常类型、HTTP 状态及白名单机器错误码，不记原始错误正文或提示词。

在 `.env` 中可配置：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `IMAGE_GENERATION_ENABLED` | `true` | 关闭设为 `false` |
| `IMAGE_GENERATION_BASE_URL` | `OPENAI_BASE_URL`，未设置时为 `https://api.openai.com/v1` | 支持 Images API 的地址 |
| `IMAGE_GENERATION_API_KEY` | 空 | 优先使用；否则使用 `OPENAI_API_KEY` 或 `api_keys_openai.txt`；双方地址均为官方 OpenAI 时还可复用面板的判断 API 密钥 |
| `IMAGE_GENERATION_MODEL` | `gpt-image-2.5-flare` | 图像模型 |
| `IMAGE_GENERATION_QUALITY` | `medium` | 输出质量 |
| `IMAGE_GENERATION_SIZE` | `1024x1024` | 输出尺寸 |
| `IMAGE_GENERATION_DAILY_CAP` | `40` | 全局每天最多发起的请求次数，设为 `0` 停用付费调用 |
| `IMAGE_USER_DAILY_CAP` / `SEARCH_USER_DAILY_CAP` | `5` / `20` | 每群每人的基础日额 |
| `IMAGE_USER_EXTRA_*` / `SEARCH_USER_EXTRA_*` | 见 `.env.example` | 按关系档位增加的额外次数 |
| `IMAGE_GENERATION_TIMEOUT_SECONDS` | `150` | 单次生成超时，单位秒 |

模型账号必须有相应的 Images API 权限和额度；判断密钥可用并不保证图像模型也可用。该功能目前是群聊文生图，不接收参考图片编辑，也不保留生成图片供后续修改。
