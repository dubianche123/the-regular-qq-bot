# 到点提醒（2026-11-02）

11-01 02:49 群主让小团团「明天早上 9 点提醒大家你回来了」，它答「9 点你们等我上线就行」。
那一轮只有分诊和聊天回复，代码里没有「几点提醒我」这回事，九点什么也没发生。
[定时任务](../scheduler.py)早就有了，催债和联网查询的跟进都挂在上面，「X 点提醒我」一直是预留的用途。

群主的要求：能设定；一个人只能有一条，新的顶掉旧的；要想好怎么删、怎么重复。

## 怎么记上

跟[画图和语音](media-replies.md)同一条原则：模型提出动作，代码核对后执行。小团团愿意记，就在回复里单独写一行：

| 写法 | 意思 |
| --- | --- |
| `〔提醒 11-03 09:00〕提醒大家小团团回来了` | 11 月 3 日 9 点提醒一次 |
| `〔提醒 每天 08:00〕提醒TA喝水` | 每天 8 点，直到取消或被顶掉 |
| `〔取消提醒〕` | 撤掉 TA 那条 |

- 只说「好，九点叫你」、不写这一行，就是没记上；写了标记也要经过下面的审核，不能当作已经保存。规则写在稳定头（`prompts.PROMPT_REMIND_RULES`）。
- 时间由小团团照着即时提示里的【现在】（`11-02 周一 21:30`）自己算，代码只认上面这种格式
  （`reminders.resolve`），不去猜「明早」「半小时后」。只写 `09:00` 算接下来的那个 9 点；
  没写年份、日子已经过了的，只有年底定明年一月那种才往后挪一年。
- 要提醒的事里不写「你」「我」：说的是它自己就写「小团团」，让它提醒的人写「TA」。到点前代码把
  「TA」换成那个人的称呼（`reminders.spell_out`）。原样交出去，到点那次生成会把「TA」当名字念出来。
- 记上了，代码在它那句话后面补一句「（记下了：11-03 09:00）」；没记上，补「（这个提醒没记上：
  这个时间已经过了）」这类原因。它自己算的时间偶尔差一天，也常常不说具体几点，群友得能当场核对。
  会话里记下标记和实际结果（`expression.record_reminder`），下一轮它看得见。
- 只在有人跟它说话的那一轮认（没叫它就接话的那几轮不认），只在群里。

## 保存前先分清意思

现有那次群聊分诊先合并问 `reminder_request`：普通聊天、查询和取消不需要写入审核，真正未定的事项先问清楚，不以直接拒绝代替提问。这一题不增加普通聊天的分诊请求次数。

模型提出创建或修改标记后，代码把当前请求、必要前文以及准备保存的时间和事项交给原生单题 `reminder_write` 审核。
它只给 `allow`、`clarify` 或 `decline` 判定，不替用户另编事项；使用本机面板里配置的原生 Decisions，未配置、禁用、超时或结果不可用归为 `unavailable`。

| 结果 | 群里怎么说 | 任务怎么变 |
| --- | --- | --- |
| `allow` | 正常事项、无害玩笑照常接话，不因某个词可能有另一层意思就主动想歪 | 时间和事项校验通过后保存，新的才顶掉旧的 |
| `clarify` | 确有未解决的歧义就中性问清楚；不能只为显得懂梗而断言用户在暗示什么 | 本轮不保存，不覆盖旧提醒；用户说清正常含义后可再记 |
| `decline` | 请求或相关前文明示要借提醒广播不当内容、羞辱或骚扰别人时，可以就地接梗，并明确这条没记 | 本次不保存，旧提醒保留 |
| `unavailable` | 说明暂时没记上，不把技术失败说成内容违规 | 本次不保存，旧提醒保留 |

回答机器人刚刚那次正式澄清时，不必再次 @：只有识别为回应它、且是说清楚的提醒续答，才恢复正式办理，仍过实际提案审核；对别人说话或没有回复来源时不扩大保存权限。

接住玩笑和保存任务是两件事。正常保存只做一次写入初审；没有保存时，最多重写一次回复，再用一道原生题核对纯正文：不能残留“已记好”等假承诺，`clarify` 要确实中性问清楚，不能一面声称懂了暗指、一面直接拒绝。
重写或核对不可用，就落到准确的本地说明，不反复生成或审核，也不因服务故障放行。
给审核模型的资料做编号脱敏；提醒事项不再直接套用昵称的身份称谓禁词，“给爸爸打电话”这类普通任务应能正常表达。
具体敏感词和机器编号仍由提醒出口检查，生成正文、本地兜底和缓存的 `ready` 都受同一边界约束。
前期提示词对比、局限与正式代码边界见[持久化提醒的审核对比与实现](persistent-task-review.md)。

### 旧版任务和审核失效

任务保存审核版本、已审事项和每日属性。旧版没有审核记录、事项或每日属性与已审版本不一致，或后来命中新加敏感词的任务，都暂停保留，仍可查询、取消；需重新说清具体事项和时间并重定。
代码不拿丢失创建语境的旧事项重新猜一次，不能把这种重审当成批准；暂停任务不会到点播报，旧的 `ready` 也会清掉。

## 一人一条

每人每群一个固定任务 ID（`reminder:群:人`）。再定一条且审核、校验通过，才是同一条改期，旧的被顶掉；即时提示里
写着 TA 现在记着哪条（「【TA 让你记着的提醒】11-03 09:00：…（再定一条就顶掉这条）」），
所以它会顺口说「原来九点那条不提醒了」，被问「我那条还在吗」也答得上来。别人的那条不受影响。
替别人定（「明天三点提醒老任交房租」）算在定的人头上。

## 到点

1. 对仍有效、已审核的任务，照着记下的事生成一句（`prompts.SYSTEM_REMIND`，跟催债一样单独一次调用，不进会话）。
   生成不出来可用本地话术「老王，到点了：……」，同样先过发送出口检查。
2. 主动发到群里（`post_to_group`），由代码精准 `@` 这条提醒的发起人。发出去了，这句记进背景里「你」说过的话。
3. 主动发不出去：写好的那句留在任务里，捎在群里下一条消息上发（`deliver_carried`，跟慢活跟进同一条路）。
4. 过点一小时还没送到就作罢。重启前错过的同理：「九点提醒大家我回来了」下午才发，比不发还糟。
5. 一次性的送到或作罢后撤掉；每天的排到下一天同一时间。
6. 群里刚喊过停（收敛期），先按住，收敛完再发。

到点生成后、主动或捎带发送前都要确认任务仍是当前那条。生成期间被取消、或批量取消已清掉的旧任务，不会因为模型刚写完又发出去。
发送出口也检查当前的敏感词与编号约束，不能靠空生成兜底或先前缓存的 `ready` 绕过。

不会重复：任务确认送达后才撤掉或改期。捎带提醒排队期间不重复入队，失败保留到下次机会；
排队后被取消、替换或过了宽限时间，旧消息不再补发。
只有兜底话送达时仍保留原提醒，不把兜底当成提醒已完成，也不把未送达的原文记进背景。
重启时任务随 `state.json` 恢复。

### 到点精准 @（2026-11-05）

任务已保存发起人的 `member_openid`；到点主动发送和稍后的捎带发送都使用这个目标，不会改成触发捎带的新发言人。
替别人定提醒仍算在发起人头上，因此 `@` 的也是发起人。普通闲聊继续用原来的纯文本路径。

`delivery.group_message_payload` 在最终 QQ 请求中使用 `msg_type=2` 和 Markdown 提及标签。
目标由代码注入，提醒正文先转义，正文里夹带的其他提及标签不会再触发 `@`。
模型输入、发送回调、引用索引、反馈缓存和日志正文只保留干净文字，不回流平台编号。
平台明确拒收格式时最多降级一次普通文字；超时、断连或空回执不换格式补发，以免重复打扰。
SDK 无法区分的错误也不当成明确格式拒收。

真实群内已发送两次测试，均取得 QQ 的成功回执。首次反馈为提及可见但未出现提示，第二次由用户确认正常，
验证了这个机器人使用 Markdown 提及的实际可用性；不以 API 200 单独判定通知成功。
该记录验收的是发送能力，不能代替内容审核与任务取消的验证。

## 删掉 / 重复

- 删自己的：群友说不要了，小团团写 `〔取消提醒〕`，只撤发起人本人在本群的那条。取消不走内容审核。
- 群主批量删：明确说“停止所有定时任务”，由本地代码直接取消本群所有群友创建的到点提醒，包括每日提醒和待捎带的提醒，取消结果先立即落盘，再按实际条数回复；普通群友无权清掉别人的提醒。
  取消还作废此前仍在分诊、生成或审核的旧请求及排队中的旧确认，避免“刚说全停了，又被旧请求补记回来”。
  已经交给 QQ 的在途发送无法撤回，代码阻止之后发起和补投的旧消息。
  这个命令只作用于本群提醒：别群提醒、后台维护和承诺催债继续运行；机器人继续运行，之后仍可新建提醒。
- 重复只做「每天」。每周、工作日、提醒三次都没做：一人一条的前提下，每天一条已经够用，再细就该用手机闹钟了。
- 最远 30 天、最近 1 分钟以后；提醒事项要同时通过语义审核和当前内容检查。

## 早期时间格式回放（luna low，按生产拼提示词）

最初时间格式提示词定稿时，每句抽 6 次，60 次全对（时间按 11-02 21:34 算）。这批只覆盖当时的时间、对象和标记，不是新增语义审核的准确率：

| 群友说 | 小团团写的 |
| --- | --- |
| 明天早上9点提醒大家你回来了 | 6 次 `〔提醒 11-03 09:00〕提醒大家小团团回来了` |
| 半小时后提醒我收衣服 | 6 次 `11-02 22:04`，`提醒TA收衣服` |
| 以后每天早上八点喊我喝水 | 6 次 `每天 08:00` |
| 明天下午三点提醒老任交房租 | 6 次 `11-03 15:00 提醒老任交房租` |
| 那个提醒改成十点吧（已有 9 点那条） | 6 次改到 `11-03 10:00`，都说了原来那条不提醒了 |
| 晚上十一点提醒我关电脑（已有 9 点那条） | 6 次 `11-02 23:00`，都说了原来那条顶掉了 |
| 我那个提醒不要了 | 6 次〔取消提醒〕（1 次只写了标记，发的是本地那句「提醒取消了」） |
| 我定的提醒还在吗 | 6 次照实答「还在，明早九点……」，没写标记 |
| 你一般几点睡觉 | 6 次都没写标记 |
| 提醒我明天交作业 | 6 次都反问几点，没写标记 |

改措辞之前那一版，「晚上十一点提醒我关电脑」4 次里有 1 次记成第二天晚上，回复里也没说几点，
这是补「（记下了：…）」的原因；「提醒大家你回来了」有一半照抄了「你」，到点就念成「老王回来了」，
这是「别用你我」那条的原因；写成「TA」原样交出去，到点会念「TA，收衣服啦」，这是 `spell_out` 的原因。
到点那句定稿后也回放过：「提醒老任交房租」开口叫的是老任，顺带说是罗老板让提醒的。
脚本在会话草稿目录，没进代码。

## 测试

`tests/test_reminders.py`：时间解析和拒绝原因、一人一条和顶掉、取消、回复里记上 / 没记上 / 没叫它不认、
到点送达、每天改期、主动发不出去捎带且不重复、过点一小时作罢不空转、错过的不补发、模型不在用本地话术、
收敛期按住、「TA」换成名字、主动与捎带均提及原请求人、捎带失败不丢提醒、排队不重复、替换旧提醒后不误删新任务。
`tests/test_delivery_mentions.py` 另覆盖提及只进最终载荷、正文转义、拒收降级、超时和空回执不跨格式补发。
`tests/test_reminder_cancel_all.py` 检查批量取消的群与类型范围、重复取消、持久化恢复和旧任务对象失效。

`tests/test_reminder_review.py`、`tests/test_reminder_transactions.py` 与 `tests/test_reminder_intent.py` 覆盖前置判断共用一次分诊、无标记也须正确问清、未保存回复核对、真实 SDK 消息对象、取消竞态与旧任务暂停。审核三道题也注册进分诊回放题库，`regular case list --cases reminder-policy` 可查看 6 条纯合成种子。
